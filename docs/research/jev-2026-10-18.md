# Jev decider measurements (17 and 18 Oct 2026)

Plan item 2 (local model to 95%, D18). This note measures the Jev decider
(`MIA_DECIDER=jev`, spec docs/superpowers/specs/2026-10-17-jev-decider-design.md) on the same
tests as the Gemma 4 12B report of 12 Oct (local-models-2026-10-12.md). Jev (TypeSafe) picks
one of 12 actions and its inputs as typed choices; code runs the tool and words the reply
(rules.compose, fi and en). No model writes text.

Setup: `jev-1.13.0` (TypeSafe's stable release; `jev-latest` points to it), confidence
threshold 0.6, egress level `pseudonymised` (names leave as Person_N tokens), the seeded demo
database, synthetic data only (D18). One request per message: about 3,700 input tokens,
0.38 s p50 and 0.47 s p95. At $0.042 per million input tokens (output is free) a message
costs about $0.00016; the whole measurement (about 7,000 requests, two train runs included)
cost under $1.50.

Two rule changes came out of the first runs, both decided on the train split and the
scenarios before the test splits were read:
- A slot answered "not stated" no longer lowers the confidence (the tool's default applies),
  and an uncertain visit pick falls back to site and date. Before this, "I'm sick today" went
  to "Did you mean" because `partial_day` (not mentioned) scored 0.47.
- `reply_only` names the work requests no action handles (pay, contracts, other agents' work,
  the dispatcher intents not built yet). Out-of-scope messages that ran a tool fell from 14.0%
  to 9.1% of the train split, with in-scope accuracy unchanged.

## After the final review fixes (18 Oct, commit 30303ad)

The branch review found paths that wrote for the wrong person or day without a question
(shared first names, an uncertain unstated date or person, a button carrying the uncertain
input) and a pseudonymiser that rewrote the request's keys for some staff names. After the
fixes the same tests give:

| | Before the fixes (sections 1 and 2) | After |
| --- | --- | --- |
| Agentic suite, mixed (48) | 39/48 (81.2%) | **38/48 (79.2%)** |
| Agentic suite, English (41) | 32/41 (78.0%) | 32/41 (78.0%) |
| Built intents, Jev's own pick, en / fi | 87.8% / 79.6% | 87.8% / 77.6% |
| Built intents, acted right, en / fi | 66.3% / 51.0% | 64.3% / 50.0% |
| Built intents, asked back, en / fi | 29.6% / 40.8% | 30.6% / 43.9% |
| Built intents, wrong tool, en / fi | 4.1% / 6.1% | 5.1% / 5.1% |
| Out of scope, ran a tool, en / fi | 8.9% / 8.6% | 8.5% / 8.5% |

The cost is on short follow-ups: "Only the morning" and "ok" now get "say it in other words"
instead of a one-button "Did you mean", because the button would have carried the uncertain
day. The eval of section 2 sends no `previous_mia_message`, so its absence_scope and
cover_reply rows are judged without the question they answer. Sections 1 to 3 below are the
measurements before the fixes.

## 1. Dispatcher agentic suite (48 scenarios, mixed languages)

| Decider | Mixed suite (48) | English suite (41) |
| --- | --- | --- |
| Jev 1.13.0, threshold 0.6 | **39/48 (81.2%)**: en 11/13, fi 13/15, fil 6/8, other 9/12 | 32/41 (78.0%) |
| Gemma 4 12B, 16k context (12 Oct) | 37/48 (77.1%) | not run |
| Gemma 4 12B, 4k context (12 Oct) | 38/48 (79.2%) | not run |
| Rules model, Sonnet 5.5 | 100% | 100% |

The failing runs, mixed and English suites together:

| Scenario | What happened | Reading |
| --- | --- | --- |
| en_scope_morning, en_scope_morning_juha, en_scope_morning_only, en_scope_all, fil_scope_morning | "Only the morning" after an absence went to "Did you mean" with the right action as the only option | the date of a follow-up answer comes from `previous_mia_message` and Jev picks it at about 0.5; the main remaining gap |

Of the 18 failed runs, 4 are format only (the scenario checks argument names Jev mode does not
use) and 2 are the unknown-site design choice. Counting those as passes would give 42/48 and
35/41, but the suite as written is the comparison, so the table reports it unchanged.

## 2. Action choice on the intent set (held-out test split)

`uv run pytest node/tests/evals/test_jev_action_eval.py -m evals -s`
(`MIA_EVAL_INTENT_LANG=fi` for Finnish)

This is not the same test as Gemma's intent classification. Gemma picked one intent id out of
the whole catalogue (every agent); Jev picks one of the dispatcher's 12 actions. So the rows
are split. **In scope**: the 13 built dispatcher intents, scored on the action. **Out of scope**:
everything else (other agents, the 15 dispatcher intents not built yet, conversation), scored
only on whether a tool ran.

| | English | Finnish |
| --- | --- | --- |
| In-scope messages | 98 | 98 |
| Jev's own pick right (before the threshold) | **87.8%** | **79.6%** |
| Acted right (after the threshold) | 66.3% | 51.0% |
| Asked "Did you mean" | 29.6% | 40.8% |
| Ran the wrong tool | 4.1% | 6.1% |
| Out-of-scope messages | 993 | 953 |
| Out-of-scope messages that ran a tool | 8.9% | 8.6% |
| Errors | 0 | 0 |

For reference only (a different task): Gemma classified the dispatcher's messages right 92.0%
(English) and 79.9% (Finnish) of the time among every agent's intents.

In-scope confusions are few and the expected ones: absence_scope and cover_reply read as each
other or as record_absence, and Finnish visit_details and checklist questions left as
reply_only. Out of scope, most tool runs go to report_site_problem: site_manager.report_damage,
purchaser.broken_equipment, conversation.hazard_report and dispatcher.lost_key. Each of those
alerts a supervisor, which is arguably right. conversation.emergency also lands there in this
eval, but in chat the safety step answers emergencies before Jev is asked. hr.sick_note going
to record_absence is the overlap D30 already names.

## 3. The threshold

The plan's rule was the lowest threshold where wrong write actions are at most 2% of all
messages. On the English train split no threshold meets it: 0.95 still gives 2.3%, because the
overlaps above count as wrong writes. 0.6 was kept:

| Threshold (English train) | In scope right | Asked back | Wrong tool | Wrong writes, all messages |
| --- | --- | --- | --- | --- |
| 0.4 | 85.8% | 7.1% | 4.0% | 9.5% |
| 0.6 | 74.8% | 19.9% | 2.2% | 7.0% |
| 0.8 | 58.8% | 37.2% | 0.9% | 4.2% |

The threshold trades questions against wrong actions; which side matters more for Hype is a
decision for the developer, not for this measurement.

## What this says for the pilot

- Jev mode beats the local Gemma on the agentic suite (81.2% against 77.1% and 79.2%) at 0.4 s
  a turn and a fraction of a cent, but it does not reach the 95% gate (D18) either.
- Its own picks are good (87.8% English, 79.6% Finnish on the built intents); what costs it
  is confidence on short follow-ups ("Only the morning", "ok"), where it asks instead of
  acting. A follow-up that answers Mia's own question could take its date and visit from the
  thread state in code instead of from Jev, as assign_cover already does.
- About 9% of messages meant for other agents run a dispatcher tool, mostly a site-problem
  alert. Before real use the router in front needs to send them to their own agents, or
  report_site_problem needs its own higher bar.
- Jev is a hosted service: real Hype messages need TypeSafe's data terms and an ADR amending
  D18 first (Q27).
