# Jev agent router evaluation on the retail set (19 Oct 2026)

Spec docs/superpowers/specs/2026-10-18-router-follow-up-design.md (decision 2 and 3). Same
question as the 18 Oct run, on retail traffic, after the `small_talk` route and the contrast
descriptions. Synthetic data only (D18). Raw results: `router-2026-10-19.raw.json` (final run,
tuned descriptions) and `router-2026-10-19-run1.raw.json` (first run, untuned descriptions).
The harness dates its file by UTC, so both were written as `router-2026-10-18.raw.json` and
renamed; the 18 Oct raw file is restored unchanged.

**Result: the gate fails, on both halves.** Gate half, six gated languages (252 cases): wrong
agent at >= 0.6 is 6.7% (gate at most 2%: fail); right is 64.3% to 78.6% per language (gate at
least 90%: fail). Two runs were allowed; this is the second.

## Setup

- Model `jev-1.13.0`, threshold 0.6, egress level `pseudonymised`, concurrency 4. One request
  per message, built by `build_request`. 1063 cases (`router_cases.py`), half `tune` or `gate`
  per case, 42 per language per half for the gated languages. 0 errors. Each run took about
  100 s (not the 15 to 25 minutes expected).
- Scoring as before, plus `small_talk`: a real message answered as small talk (a miss, counted
  apart from wrong). Gate asserts read the gate half of en, fil, ceb, hil, war, bcl only.
- Run 1 used the committed descriptions. After it, I edited the descriptions once (the run had
  finished; nothing was edited while a run was going), then ran again. Run 2 is the result.

## What changed since 18 Oct

- Greeting and thanks with no active agent are now `small_talk` (lead agent answers), not
  buttons. All 12 gate-half `any` cases in the gated languages are right; across all languages
  `any` is 75.1% right, 24.9% still ask (Jev picked an agent below 0.6 or `unclear` where the
  message was not small talk).
- Descriptions carry a "; not ..." contrast line.
- The set is retail traffic, 1063 cases, ten languages, with the in-flow replies gone. 970 old
  cases are not comparable: right moved from 52.6% to 70.1% overall, ask from 44.5% to 21.9%,
  but wrong rose from 1.2% to 2.7% overall.

## Reading

- **Small talk works, wrong agent got worse.** The ask rate halved (44.5% to 21.9%) and every
  gate-half greeting in the gated languages is right. Wrong rose to 6.7% on the gate half
  because the retail set is harder at the seams between neighbours.
- **The wrong routes cluster in a few message types**, which is why tuning on one half moved
  only that half: adding a person ("add Maria as clerk", branch manager) goes to HR in five
  languages (8 gate cases); "drawer is short 150" (bookkeeper) goes to inventory because
  "short" reads as stock; sales questions such as "best day this month" go to the shift
  supervisor. Hiring is in the HR description and "people and their roles" in the branch
  manager's, so they collide by design; the contrast line does not settle it.
- **Missed switches and asks remain.** The sales supervisor is the weakest (41.2% right, 15.5%
  missed switch): with another agent active, a sales report is kept by the active agent. 18%
  ask is mostly the shift supervisor's own messages (Jev picks it below 0.6 or `unclear`).
- **Not a model-size or latency problem**: 0 errors, 0.42 s p95.

## What remains

1. The gate is not met. Another tuning pass needs fresh failure types (the gate half is spent
   as a measure once looked at); the clearest fixes are in descriptions, not the threshold:
   settle who owns "add a person" (hire = HR, add to a branch = branch manager?) and "drawer
   short" (cash count = bookkeeper).
2. Missed switches need a rule in code (D rule 7): a strong item-name match to another agent's
   description should beat an active agent kept at low confidence.
3. Finnish, Ilocano, Kapampangan and Pangasinan stay reported only.
4. Decide whether 90% right per language is the right bar given asks are safe (wrong is the
   harm, ask is a button); see the gate in the spec.
