# Jev agent router evaluation (18 Oct 2026)

Spec docs/superpowers/specs/2026-10-18-multi-agent-routing-design.md (Testing, Real Jev). Does
the Jev router (`mia/chat/agent_router.py`) send a message to the right one of six agents,
in English, Finnish and the Philippine languages? Synthetic data only (D18). Raw results:
`router-2026-10-18.raw.json` (every case with its route, confidence, latency and tokens).

**Result: the gate fails.** Wrong agent at >= 0.6 is 1.2% (gate at most 2%: pass), but right
agent is between 50% and 83% in the six gated languages (gate at least 90%: fail). Almost all
of the shortfall is ask-back ("Is this about" buttons), not wrong routing.

## Setup

- Model `jev-1.13.0`, threshold 0.6, egress level `pseudonymised`, concurrency 4, the seeded
  demo branch. One request per message: the router request exactly as `build_request` makes it.
- Agents: all six, in roster order (sales supervisor, shift supervisor, inventory manager,
  bookkeeper, HR officer, branch manager) plus `unclear`. Router descriptions as committed in
  `agents/stubs.py` and `agents/shift_supervisor/turn.py`; none were tuned for this run.
- Scoring: right when the routed agent is the expected one (or, for greetings, thanks and the
  conversation intents, `expected = any`, any agent that is not an ask); wrong when Jev
  switched to or chose another agent at >= 0.6; ask when the router asks; other when the
  active agent was kept although another was expected (a missed switch).
- Cases (`node/tests/evals/router_cases.py`), 970 in all:

| Group | What | Cases |
| --- | --- | --- |
| single | intent test split: shift supervisor intents (en 174, fi 174) and conversation intents (en 146, fi 146), no active agent | 640 |
| single | language spike: 20 messages per language (reports, stock, questions, greeting, thanks, "I will be late tomorrow") x 9 languages, no active agent | 180 |
| follow_up | spike answers to "Why do you think sales went well?", the sales supervisor active | 90 |
| switch | 10 per language for en, fil, ceb, hil, war, bcl: 5 sales reports with the shift supervisor active, 5 cover or absence messages with the sales supervisor active | 60 |

Per language: en 360, fi 320, fil, ceb, hil, war, bcl 40 each, ilo, pam, pag 30 each.

## Reading

- **The router rarely sends a message to the wrong agent.** 12 of 970 at >= 0.6. The safety
  half of the gate holds, including in the weak languages (Ilocano and Pangasinan have most of
  the 12).
- **Ask-back is the failure, and most of it is the case set, not routing.**
  - 74.5% of the `any` cases ask. Every greeting and thanks in every language goes to
    `unclear`, mostly at 0.8 to 0.95. With no active agent that is the "Is this about"
    buttons. The conversation intents (feedback about Mia, insurance, pets, payday, emergency,
    privacy) belong to none of the six agents, so `unclear` is a fair answer for them too.
    Excluding `any`, right is: en 67%, fil 84%, ceb 53%, hil 87%, war 82%, bcl 66% (fi 58%,
    ilo 50%, pam 75%, pag 46%).
  - Many shift supervisor intent rows are replies inside a flow ("all of them pls", "deal",
    "Mikael.", "the second one, Maria", "ok i'll take it"). The eval sends them with no active
    agent and no previous Mia message; in the chat a pending question skips the router (spec,
    A turn, step 5), so these cases measure something the product never asks Jev.
  - 177 of the 432 asks are `unclear` picked at >= 0.6: Jev is sure the message fits no single
    agent, not unsure which one.
- **Follow-ups work** (96.7%): with the sales supervisor active and its question as previous
  message, the answers stay with it in every language.
- **Switching away from the shift supervisor is weak in the Visayan and Bikol languages.** 16
  sales reports with the shift supervisor active were kept by it (ceb 5, bcl 5, war 3, hil 2,
  fil 1), most with the sales pick below 0.6 or the active agent picked. In English none was
  kept (four switched, one went to the inventory manager). Cover messages with the sales supervisor active switched in every language.
- **Stock and sales are close neighbours.** "3 boxes of four bibingcute were bought this
  morning" and "an office ordered 20 boxes" go to the inventory manager; "Overload is almost
  gone" went to the shift supervisor.

## What to change (a later task; nothing was tuned here)

1. Fix the case set before tuning: give in-flow shift supervisor replies their active agent and
   previous message (or drop them, since a pending question skips the router), and score
   greetings and thanks with an active agent, where `unclear` keeps it.
2. Decide what a greeting with no active agent should do. Options: route `unclear` at high
   confidence to the person's first agent instead of buttons, or answer greetings and thanks
   in shared code before routing (like the safety steps).
3. Sharpen the descriptions where neighbours collide: the sales supervisor owns "items bought
   or ordered by customers, boxes sold"; the inventory manager owns "what is left", not what
   was bought; "almost gone" is stock.
4. Re-measure switching from the shift supervisor in ceb, bcl and war after 3; if it stays
   weak, consider a lower bar for a switch to an agent whose description the message matches
   on item names (code, rule 7), not a lower threshold for everyone.
5. Ilocano and Pangasinan stay reported only; Pangasinan routing is not safe (13% wrong).

Note: the run recorded routes and confidences but not Jev's raw pick for an ask; the eval
now also stores `picked`, so the next run can separate `unclear` from a low-confidence agent.
